# 代理冲突测试夹具

验证 `docs/test-plan.md` §5.4（DoD #14）用的一次性扩展：**代理设置被另一个扩展控制时，
LostProxy 必须拒绝开启、说明原因，且开关不能亮。**

制造这个状态需要第二个扩展来抢 `chrome.proxy`，这个夹具就是那第二个扩展。

## 为什么不用 SwitchyOmega

- 原作者 2025 年 1 月停止维护，原版是 Manifest V2。**Chrome 138（2025-07-24）移除 MV2
  支持后，它在所有 Chromium 浏览器上都无法运行**，Edge 同理。Edge 商店自 2026 年 8 月
  起下架 MV2 扩展，所以现在搜不到是正常的。
- 商店里同名的条目多为第三方重写，来源不一。其中一个假 fork 在 2024 年 12 月
  被用于供应链攻击，影响约 260 万台设备。

为跑一次五分钟的测试，去给一个未经审计的扩展授予全部浏览器流量的访问权，不成比例。
这个夹具总共约 30 行，你可以读完再装。

## 它做什么、不做什么

| | |
| --- | --- |
| 申请的权限 | 只有 `proxy` |
| 网络请求 | 无 |
| 读取的数据 | 无 |
| 代理指向 | `127.0.0.1:9`（discard 端口，本机必定无人监听） |

指向一个**必然连不通**的地址是刻意的：它的作用是"占位"，不是"能用"。
这样即便忘了删，它也不会把流量送到任何地方 —— 只会让网页打不开，
而那是一个立刻能被发现的故障。

## 用法

```text
1. edge://extensions → 打开「开发人员模式」
2. 「加载解压缩的扩展」→ 选本目录（tools/conflict-test-extension）
3. 装上即生效，图标显示 ON 徽章
```

然后验这两步：

| # | 操作 | 期望 |
| --- | --- | --- |
| **L1** | 点 LostProxy 的开关 | 拒绝开启 + 告警「正被另一个扩展控制，不会强行覆盖」，**开关不亮** |
| **L2** | 点本夹具的图标（徽章消失 = 已释放）→ 再点 LostProxy 的开关 | 正常开启 |

**L1 要盯的是开关状态。** 开关亮了但代理没生效就是**假 ON**，属于 bug 而非环境问题。

## 测完请删掉

`edge://extensions` → 找到 **ZZ Proxy Conflict Fixture** → 移除。

名字以 `ZZ` 开头是为了排在列表末尾，方便找。

留着它的后果是它会持续占用代理设置，LostProxy 一直开不起来 ——
症状明显，但没必要给自己添这个麻烦。

## 关于扩展优先级

Chromium 的规则是**最近安装的扩展优先**。所以这个夹具装完之后它优先级更高，
LostProxy 会被挡住 —— 这正是要验的方向。

若出现反向情况（LostProxy 仍能开、夹具被挡），把 LostProxy 停用再启用一次，
它就变成"最近的"了，冲突方向会反过来。两个方向都是正常的平台行为。
